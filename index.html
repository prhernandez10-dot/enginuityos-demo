Operating platform for the aviation aftermarket

ERP manages transactions. EnginuityOS governs the decisions.

Buying, repairing and selling aircraft parts and engines involves hundreds of decisions: which quote to approve, when a part can be sold, who chases a late repair. EnginuityOS records each one, makes sure the right person makes it, and keeps a record nobody can quietly change. AI can advise, but people decide.

The six rules the platform never breaks

  • G1Nothing is overwritten. Every fact is saved as a new record in a chain that shows any tampering.
  • G2When in doubt, refuse. A missing permission or setting stops the action instead of guessing.
  • G3One writer per record. Two people can't silently overwrite each other.
  • G4Replayable. The full state can be rebuilt from the saved records and comes out identical.
  • G5Companies are sealed off. One customer can never see or touch another's data.
  • G6AI never decides. AI can recommend; only an accountable person can approve.

How this demo works

The part-repair walkthrough runs the platform's own code in your browser. The engine-deal walkthrough is a recorded run of the real deal workflow. Nothing is faked, and the things that differ from a server deployment are listed here.

What runs

  • The material ledger: purchased packages, units, repair orders, quotes and approvals, alert rules that turn into owned tasks, quality acceptance, sale, and the cost recovery review.
  • The governed deal workflow (recorded): opportunities, deals, evidence with second-person verification, compliance, approval gates with co-approval, award, settlement, title, record lock, audit export and replay. The run was recorded by executing the real workflow; the page shows each step's result and the records it left, and the stored records' hash chain is verified live by the same code a server uses.
  • The kernel and the durable journal: the append-only event record, the SHA-256 hash chain and AES-256-GCM encryption of stored details, using the same code a server uses with PostgreSQL.
  • Identity rules: every action is checked against the person's role, their company and whether they are a human, a service or an AI.

What differs from a server

  • Records are kept in memory in your browser by the platform's own in-memory SQL client, the one its tests use, instead of PostgreSQL. Reloading the page clears them.
  • Hashing and encryption use audited open-source JavaScript libraries in place of the server's built-in crypto module. The encryption key is a fixed demonstration key.
  • Everyone in the walkthroughs is a role, not a real sign-in. A real deployment signs people in with their company's Microsoft account.
  • The rules and limits come from the platform's synthetic test policy (for example, a $25,000 repair approval limit). A real customer sets its own.
  • Dates in the walkthroughs are fixed so every run gives the same result.

What it does not show

The full operator console, engine valuation, the fleet data service and connections to a customer's ERP system run on the server and are not part of this page.
